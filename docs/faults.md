# Испытания при исчерпании места

На Windows с Python 3.14.10 выполнены два сценария. Команда запуска из корня проекта:

```console
python -m unittest discover -s tests -p test_faults.py -v
```

## Обрыв записи файла

Агент обрабатывал выданный координатором блок с одним ID. Первая запись сохранила 65 536 байт в `video.mp4.part`. При второй записи тест вызвал `OSError` с системным кодом `ENOSPC` непосредственно в методе записи потока. Обычный диск при этом сохранял свободное место. Путь от загрузки до возврата блока использовал методы рабочего агента и транзакции координатора. Для этой проверки тест подставляет источник байтов в памяти и вызывает методы протокола между компонентами в одном процессе.

Координатор получил причину `insufficient_disk`. Проверены возврат блока и приостановка выдачи этому узлу при нулевом настроенном резерве диска. Heartbeat с нулевым свободным местом сохранил блокировку. После heartbeat с достаточным запасом агент получил тот же блок с новым номером попытки. Первая половина файла сохранилась, а запрос продолжения начался с байта 65 536. При успешной докачке содержимое совпало с эталоном, временный файл исчез и в БД появилась одна запись готового файла.

## Настоящая ошибка заполнения SQLite

На действующем соединении записи координатора тест ограничил `PRAGMA max_page_count` текущим числом страниц временной БД. Первый ID уже был подтверждён. Попытка сохранить второй ID с 128 КиБ метаданных потребовала дополнительных страниц. Движок SQLite вернул **`SQLITE_FULL`**, что тест проверил по числовому коду исключения. Транзакция откатилась. В БД сохранился первый ID, а контрольная точка по-прежнему указывала на второй.

После ошибки координатор закрыл соединение записи. Тест убедился, что старый объект соединения больше не выполняет запросы. Следующая транзакция открыла новое соединение. После увеличения лимита координатор дважды принял один и тот же результат через метод обработки отчёта агента. Задание завершилось, в БД остались ровно два ID, а `PRAGMA integrity_check` вернул `ok`. Лимит действовал в одноразовой БД. Тест не изменял квоты файловой системы.

## Отдельный сценарий для Linux

```console
python verify_disk.py
```

Для запуска нужны Linux, утилиты `unshare`, `mount`, `umount` и разрешённые пользовательские пространства имён. Скрипт создаёт отдельные пространства имён пользователя и монтирования, затем монтирует пустой tmpfs объёмом **2 МиБ**. Тест сверяет тип и точку монтирования через `/proc/self/mountinfo` и проверяет верхнюю границу файловой системы. После проверки свободного места агентом конкурентный процесс записи моделируется дополнительным файлом в tmpfs. Перед вторым вызовом записи этот файл занимает оставшиеся страницы. В этой конфигурации `ENOSPC` должна вернуть операция записи ядра. По освобождении места проверяется докачка. Скрипт снимает монтирование при выходе.

На текущем стенде Windows подсистема WSL отсутствует. Прогон по умолчанию вернул **два успешно пройденных теста и один пропуск**. Сценарий с настоящей ошибкой записи ядра Linux подготовлен для отдельного запуска.
