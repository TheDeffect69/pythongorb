# Руководство оператора

## Подключение

Откройте адрес координатора в браузере, нажмите «Войти» и введите токен, полученный у администратора стенда. Панель обращается к API по адресу текущего сайта. Токен находится в памяти вкладки. При перезагрузке страницы потребуется повторный вход. Для удалённого доступа используйте HTTPS, настроенный администратором.

Роль viewer разрешает чтение. Для изменения заданий требуется роль operator или administrator. Раздел аудита доступен администратору. Ограничения проверяет API при каждом запросе.

## Создание задания

1. Убедитесь, что во вкладке «Серверы» видны узлы, зарегистрированные агентами. Узел появляется после запуска агента с параметрами доступа к координатору.
2. Нажмите «Создать задание». Для короткой проверки укажите конечный диапазон, например `[0,99]`. Обе границы включаются. Запись `99` даёт такой же результат. Запись `[80,]` обрабатывает идентификаторы начиная с 80 до условия завершения, пустое поле запускает открытый диапазон с нуля.
3. Задайте потоки на узел, размер блока, общий лимит запросов, число повторов, тайм-аут и резерв диска. Для наблюдения за распределением размер блока должен быть меньше длины диапазона. При необходимости выберите конкретные рабочие узлы.
4. Нажмите «Создать», откройте строку задания и нажмите «Запустить». Проверьте, что растёт счётчик обработанных ID.

## Ход работы

Сводка в верхней части страницы показывает число работающих заданий, доступных серверов, обработанных ID и загруженных файлов. Выберите задание, чтобы увидеть его диапазон, прогресс, скорость, оставшееся время и историю. Для открытого диапазона время завершения неопределённо. Панель запрашивает новые данные каждые три секунды. При недоступности API она сохраняет время последнего успешного обновления и показывает ошибку.

«Мягкая пауза» прекращает выдачу новых блоков и позволяет закончить текущие операции. После перехода в состояние «На паузе» доступна команда «Продолжить». «Остановить» требует подтверждения и отменяет активную работу с сохранением прогресса. После окончательных ошибок используйте команду «Повторить ошибки», когда она доступна для выбранного состояния.

В настройках задания изменяются потоки, общий лимит запросов и отдельные лимиты проверок и загрузок. Для индивидуальной настройки откройте сервер и нажмите «Настройки узла». Здесь задаются потоки и три независимых предела узла — общий, для проверок и для загрузок. Пустое значение снимает индивидуальное переопределение. Там же можно отключить и снова включить узел. Страница показывает последний heartbeat, версию агента, текущий блок и переданные агентом показатели. Доступность системных метрик зависит от платформы агента.

## Управление службой на сервере

Администратор может выбрать узел в разделе «Серверы» и открыть блок «Служба агента по SSH». Кнопки доступны для узлов, включённых в SSH-инвентарь координатора. Доступность heartbeat и SSH проверяется отдельно: служба может быть остановлена на сервере, который по-прежнему доступен по SSH.

«Проверить службу» запрашивает текущее состояние. Успешный ответ подтверждает, что служба активна. При ошибке проверки панель покажет сообщение координатора. «Запустить службу», «Перезапустить службу» и «Обновить агент» требуют подтверждения с именем выбранного сервера. После операции проверьте время последнего heartbeat и версию агента. Журнал действий доступен в разделе «Аудит».

## Проверка результатов

В карточке задания «Блоков в очереди» учитывает сформированные блоки, ожидающие выдачи. «Старейший блок в очереди» показывает время его ожидания. В открытом диапазоне будущие блоки создаются по мере работы. «Последний прогресс» — время подтверждения результата, до первого результата показывается время старта задания.

Выберите задание, задайте фильтр по числовому ID или статусу. В режиме «Текущие состояния» отображаются в том числе незавершённые ID. Нажмите на ID, чтобы открыть историю переходов между состояниями. Таблица выводит записи страницами. В режиме «Результаты» команда «Скачать CSV» запрашивает у координатора выгрузку по выбранным фильтрам. Раздел событий показывает диагностику и операции по заданию. Фильтр событий работает по записям, загруженным в панель. Аналогичный поиск доступен в разделе аудита.

## Разбор сбоев

Сводка предупреждений над списком заданий пересчитывается при опросе координатора. Пороговые значения стенда применяются следующим образом.

- Для включённого узла задержка heartbeat превышает 1,5 его интервала. По истечении двух интервалов координатор считает узел недоступным для работы. Статус берётся из связи с агентом; состояние самой машины по сети отдельно не измеряется.
- Резерв диска проверяется для текущих заданий, которым разрешён данный узел. При CPU или занятой доле RAM от 90 % появляется предупреждение о нагрузке. Сравнение версии использует ожидаемую версию агента, переданную координатором.
- Для задания в работе интервал без подтверждённого результата от 60 секунд вызывает предупреждение. Длительная проверка или скачивание большого файла тоже может дать такой сигнал.
- Скорость обработки сравнивается за два соседних окна около 30 секунд. Предупреждение возникает при падении минимум вдвое, если за предыдущее окно было подтверждено хотя бы 10 ID.
- Для узла окно наблюдения составляет не менее 30 секунд и не менее одного интервала heartbeat. Границы окон привязаны к полученным измерениям. Предупреждение об ошибках появляется при трёх и более новых окончательных ошибках и росте их частоты минимум вдвое относительно предыдущего окна. Для предупреждения о 429 требуется минимум пять таких ответов и доля не менее 20 % запросов за последнее окно.
- Панель накапливает историю для сравнений, пока открыта вкладка. После перезагрузки страницы, длительного разрыва измерений или сброса счётчиков требуется накопить свежие данные. Для сравнения времени heartbeat и прогресса часы компьютера оператора и координатора должны быть синхронизированы.

- При ошибке обновления проверьте доступность координатора, роль и срок действия токена. До следующего успешного обновления ориентируйтесь на время возле заголовка.
- При потере heartbeat откройте «Серверы» и проверьте время последней связи. После истечения аренды незавершённую работу может получить другой узел.
- При недостатке диска сопоставьте свободное место с резервом задания. Дождитесь освобождения места или подключите другой узел.
- При ответах 429 проверьте частоту запросов, счётчики повторов и события. Для ручного снижения общего лимита откройте настройки задания.
- При отказе в доступе к материалу проверьте статус результата. Для проверки сценариев используйте управляемый HTTP-сервис стенда.
